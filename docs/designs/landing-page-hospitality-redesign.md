# Design: Landing Page — Hospitality Visual Identity

Generated by /plan-ceo-review on 2026-09-23
Branch: main
Repo: robertangeles/cc-culinaire-kitchen
Mode: Hold Scope (rework of an existing surface, not a new product)

## Problem

Real customer feedback — from Ches and multiple restaurant-owner customers — is that the front page (`/`, `LandingPage.tsx`) "looks vibe-coded," not professional. Confirmed directly with the founder: this is not a copy-quality problem, and not primarily a missing-social-proof problem. The visual system itself reads as generic dark-mode tech/AI SaaS, not software built for chefs and restaurant owners. Pushed for specificity: "Doesn't look like restaurant/hospitality software."

## Root cause (verified by reading the actual code)

- `packages/client/src/components/landing/` — 14 components, ~1748 LOC.
- Single centralized palette, `packages/client/src/styles/globals.css:6-21`: a near-black neutral scale (`--color-dark` … `--color-dark-600`) plus one warm-gold accent (`--color-gold*`, `#D4A574`). This exact combination — dark background, one warm-amber accent, serif display font, framer-motion staggered fade-ins — is a common AI-startup landing page pattern. It's competently executed (not glassmorphism/gradient-overload slop), but the genre itself reads as tech SaaS, not hospitality.
- Zero real photography anywhere on the page. Every visual is a hand-built synthetic SVG/CSS mockup: `PhoneMockup.tsx`, `ReceivingMockup.tsx`, `LocationMap.tsx`.
- `TrustStrip.tsx` shows 6 generic category labels ("Fine dining kitchens", "Casual dining groups", …), not real customer names, logos, or a count. Zero testimonials anywhere.
- By contrast, `Pricing.tsx` copy is genuinely good: a real competitor comparison table with specific dollar figures (ChefTec $200+/mo, MarketMan $239/mo, BlueCart $149/mo). Not part of the complaint — left alone.

## Direction (founder-confirmed): "Working kitchen"

Warm, high-contrast editorial photography of real kitchens, chefs, and plating — the Bon Appétit / Noma editorial register, not stock-photo SaaS imagery. Palette moves off near-black toward warm cream/charcoal with a grounded copper/amber accent (not neon, not glowing). Product visuals shown in physical context (e.g. a phone resting on a stainless prep counter) instead of floating glossy 3D renders. Editorial confidence over SaaS flash — closer to a hospitality trade publication than a demo product page.

## Scope

### In scope
1. **Palette rework** — single-file change: `globals.css:6-21` token block (near-black + gold → warm cream/charcoal + copper). Centralized token, so this alone changes the register of all 14 components without touching their JSX.
2. **Hero.tsx** — swap the radial gold-glow background for real kitchen photography; re-ground `PhoneMockup` in a photographed scene rather than floating with a glow shadow.
3. **Real product visuals** — replace `PhoneMockup.tsx` and `ReceivingMockup.tsx` synthetic SVG mockups with actual app screenshots.
4. **TrustStrip.tsx → "Featured customer" callout** — first real customer confirmed: Almost French Patisserie. Logo in place at `packages/client/public/logos/almost-french-patisserie.png` (179×239 PNG). Decision (2026-09-23): ship now, sized honestly for one — a featured-customer callout (logo + short line), not a multi-logo row implying a customer base that doesn't exist yet. Re-expand to a logo row once 2-3 more customers are on board.
5. **Section-break photography** — `DayInTheLife.tsx`, `GMSection.tsx`, `MultiLocation.tsx` are currently text/synthetic-only; add real photography to carry the "working kitchen" signal past the hero, not just at the top of the page.
6. **Typography unchanged** — Cormorant Garamond (serif display) + DM Sans (body) already read as editorial/hospitality-trade-appropriate. Not the diagnosed problem.

### Explicitly out of scope
- `Pricing.tsx` copy/comparison table.
- Page structure, section order, IA.
- Motion system (`framer-motion` stagger/fade) — not named as an issue.
- The app-interior "Infection Virus" design standard (glass morphism, amber glow) from `CLAUDE.md` — that governs the logged-in product, a separate system from the public marketing page. Not applicable here.

### Blocked on founder input (can't fabricate)
- Real product screenshots — needs a capture pass against the running app (or existing marketing assets). Not AI-generatable without it just being another synthetic mockup, which is the exact thing being replaced.
- ~~Real customer names/logos~~ — unblocked 2026-09-23: first real customer (Almost French Patisserie) confirmed, logo pending file drop. Shipping as a single-customer "Featured customer" callout rather than waiting for more.

### Not blocked — can be AI-generated
- **Kitchen/food photography** (hero background, section breaks) — generate via the same `gstack design` tool used for the mockups below (`~/.gstack/openai.json` key already works). No licensing/commissioning needed. Needs a visual QA pass per image — AI generation can glitch (see variant B's garbled logo text below) — but this removes what was previously flagged as a real budget/logistics blocker.
- CulinAIre Kitchen's own wordmark/logo is unaffected by any of this — it's not in scope, it already renders correctly in all 3 mockups below.

## Sequencing

1. Palette rework first — cheapest change, immediately shifts every component's register, lets you sanity-check the direction against Ches before spending on photography/screenshots.
2. Source real photography + real product screenshots (founder-blocked step).
3. Hero.tsx + PhoneMockup/ReceivingMockup rework once assets exist.
4. TrustStrip real customers (parallel — just needs founder to collect names/logos).
5. Section-break photography last — highest LOC touch, lowest urgency (hero + trust strip carry most of the first-impression weight).

## Visual exploration

3 hero mockups generated via gstack's `design` tool for the "working kitchen" direction:
`~/.gstack/projects/robertangeles-cc-culinaire-kitchen/designs/mockup-20260923/variant-{A,B,C}.png`

All three converge on the same language, which validates the direction: warm editorial
kitchen photography as the dominant visual, phone mockup grounded on a stainless prep
counter (not floating/glowing), warm cream/charcoal-black base with a copper/amber accent
(not neon gold), serif display type, real-feeling trust strip of restaurant wordmarks.

**Recommendation: Variant C.** Cleanest information hierarchy in the phone mockup (prep
timeline + per-station breakdown reads as real software, not a mocked screen), tightest nav,
"Trusted by chefs and operators" framing over the more generic "Trusted by leading kitchens."
Variant A is a close second — its stat-ring UI is the most polished single element of the
three. Variant B has a rendering glitch (garbled "??????" in place of one logo) and includes
a real restaurant chain name (Hawksmoor) that can't be used without permission — same problem
applies to every made-up logo/name across all three variants (Porto, Sage, Iron & Oak, Forno
Cultura, Margot, Après, etc. are all AI-fabricated, not real customers). These mockups are a
**direction validator, not a shippable asset** — the real build needs real customer names/logos
(the founder-blocked item above) and licensed or commissioned photography, not this generated
imagery, before anything ships.

## Implementation status (2026-09-23)

Branch: `feature/ck-web/landing-hospitality-redesign`.

**Corrected before implementing:** the palette-rework plan above (item 1, "single-file
change: `globals.css:6-21`") was wrong. `--color-dark`/`--color-gold` are not landing-only —
they're the shared dark-mode design tokens used across the entire authenticated app (~150
files). Repainting them in place would have re-skinned every logged-in page, not just the
marketing page. Fixed by adding a **new, separate token namespace** instead
(`--color-cocoa*` / `--color-copper*`, additive in `globals.css`) and repointing only the 14
landing components + `LandingPage.tsx` at it. The app's existing `--color-dark`/`--color-gold`
tokens are untouched.

**Shipped:**
1. Palette rework — done, via the corrected approach above.
2. Hero.tsx — done. Real kitchen photography (AI-generated: warm editorial shot, chef
   plating on a stainless counter) as the background, replacing the radial-glow div, with a
   scrim gradient for text legibility. `packages/client/public/photography/hero-kitchen.png`.
3. PhoneMockup.tsx — done, partially per scope. Replaced the fabricated JSX prep-list UI with
   a **real screenshot** captured via Playwright against the live `/inventory` dashboard
